# 아모리안 챌린지 조합 도우미

- 경로: `/pq/amorian-solver`
- 진입: `/pq`, `/wedding`, 가이드 메뉴, 통합검색(아모리아/아모리안/웨딩/엘리아스/발판/밧줄/조합표)
- 참조 자료: 사용자가 제공한 길드원 제작 `amoria_pq_solver_easy_v4_movement.html`
- 공개 화면에는 길드원 기여를 표시하며, 제작자 실명·닉네임은 제공받지 않아 임의로 기재하지 않는다.

## 데이터와 규칙

원본 HTML의 `DATA.rope`, `DATA.platform` 결정 트리를 `web/data/amorianSolver.json`에 그대로 옮겼다. 원본의 전체 스타일·전역 키보드 처리·HTML 삽입 코드는 사용하지 않고 React와 사이트 테마로 다시 구현했다.

- 밧줄: 5명을 A/B/C 3개 밧줄에 배치하는 21가지 조합. 결과는 정확히 인원이 일치하는 밧줄 수 0/1/3. 2개가 맞으면 나머지도 맞으므로 결과 2는 없다.
- 발판: 9개 중 5개를 고르는 126가지 조합. 결과는 선택한 정답 발판 수 1~5. 두 5원소 집합은 9개 공간에서 적어도 1개가 겹친다.
- 발판 표기: 위 `A, 2, B, 3` / 아래 `C, 6, D, 9, 5`. 원본의 내부 번호 1~9와 게임 표시 문자를 혼동하지 않는다.
- 원본 경로를 따를 때 밧줄 최대 4회, 발판 최대 5회 **결과 입력**으로 후보가 하나가 된다. NPC 클리어 판정을 받지 않고 추론된 경우 마지막 이동 후 NPC 확인이 추가로 필요할 수 있다.
- 이동은 이전 배치에서 빠지는 인원/발판을 다음 배치의 부족한 곳에 연결한다. 캐릭터별 실제 지형 최단 경로 또는 모든 전략에 대한 전역 최적성을 보장하는 문구는 사용하지 않는다.
- 원본 규칙의 수학적 일관성을 검증한 것이며, 실제 인게임 런을 대신 검증한 것은 아니다.

## 저장·접근성

`maple-amorian-solver-v1` localStorage에 모드와 결과 배열만 저장한다. 저장된 노드/정답을 신뢰하지 않고 매번 결정 트리를 재실행한다. 불가능한 결과, 정답 이후 추가 입력, 버전 불일치 또는 손상된 데이터는 복원하지 않고 안내한다. 두 퍼즐의 이력과 초기화는 독립적이다. 저장소가 차단돼도 현재 세션의 풀이를 계속할 수 있다.

단축키는 도우미 영역에서만 동작한다. 검색/입력 필드, modifier key, key repeat를 제외한다. 상태 변화는 live region으로 알리고, 발판 선택 여부는 색뿐 아니라 텍스트로도 표시한다. API 쓰기나 계정/서버 저장 기능은 없다.

## 검증

```sh
npm run test:amorian
cd web
npm run build
```

`scripts/test_amorian_solver.cjs`가 147개 정답을 전수 순회하며 모든 경로의 후보 수/분기/정답/확인 횟수, 최소 이동 인원, 되돌리기 및 복원, 손상 데이터 처리를 검사한다. 기존 web의 TypeScript 의존성으로 순수 모듈을 메모리에서 컴파일하므로 추가 테스트 의존성은 없다.

2026-09-08 검증 결과:

- 원본 파일의 두 결정 트리와 가져온 JSON의 deep equality 확인.
- 147개 전체 정답 경로와 기존 Python 테스트 31개 통과.
- TypeScript 검사 및 production build(76개 정적 페이지) 성공.
- Chrome 모바일 390px 라이트/다크에서 새 페이지 main 영역 axe WCAG A/AA 검사 위반 0개, 문서 가로 넘침 없음.
- 브라우저에서 결과 입력, 모드별 기록 유지, 새로고침 복원, 되돌리기, 현재 퍼즐만 초기화, 추론/클리어 표시 차이, 단축키 및 입력창 격리, 손상 기록/해당 저장 키 쓰기 실패 대응을 확인.
- 자동 접근성 검사는 실제 스크린리더/인게임 검증을 대체하지 않는다.
