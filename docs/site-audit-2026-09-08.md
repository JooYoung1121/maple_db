## 3. UI/UX·가독성

### 유지할 점

픽셀·메이플 분위기는 사이트 성격과 잘 맞는다. 검색 중심 홈, 접을 수 있는 사이드 메뉴, 이미 있는 `오늘 뭐 하지?`·캐릭터 설정 연결도 좋은 기반이다. 모바일 주요 화면의 큰 레이아웃 붕괴는 관찰되지 않았다. 배틀메이지 가이드의 공식/원작/커뮤니티 구분 설명도 방향은 좋다.

### 먼저 개선할 점

1. **명도 대비**: `/quests`의 데이터 주의문은 밝은 배경에 `text-amber-300`을 사용해 대비가 약 **1.12:1**이다. 읽어야 할 경고가 특히 안 보인다. 모바일 퀘스트 첫 화면에서 대비 위반 요소 21개가 검출됐고, Tip 버튼도 약 2.97:1이었다. 일반 텍스트의 AA 기준은 4.5:1이다. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
2. **필터 레이블**: `/items` select 4개, `/skills` 2개, `/quests` 1개에 접근 가능한 이름이 없다. 눈에 보이는 문구가 있어도 `label/htmlFor` 연결 또는 `aria-label`이 필요하다.
3. **본문 글꼴·크기**: 9~11px 보조 문구가 많다. `/skills` 첫 화면의 12px 미만 텍스트 요소는 21개였다. 크기만으로 WCAG 위반이라고 할 수는 없으나 긴 설명·근거·수치 가독성에는 불리하다. **재확인 정정:** `layout.tsx`의 본문은 이미 Pretendard/system-ui이므로 전역 본문 글꼴 교체는 필요하지 않다. 픽셀 브랜딩을 유지하면서 작은 보조 문구를 개선한다.
4. **표 조작**: 모바일 배메 가이드의 가로 스크롤 표에 키보드 포커스 경로가 없다. 포커스 가능한 컨테이너/설명과 명확한 스크롤 힌트를 추가한다.
5. **홈 정보 밀도**: 큰 검색 히어로, 상단 검색, 고정 검색 버튼이 겹친다. 모바일 첫 화면 아래로 필요한 도구가 밀린다. 검색 진입점의 역할을 정리하고 기존 `오늘 뭐 하지?`에 이벤트 마감·PQ 재입장을 묶는 편이 유용하다.
6. **터치·움직임**: 작고 반복되는 Tip/아이콘 버튼의 터치 면적을 넓힌다. 24px 최소 기준은 예외/간격 조건까지 확인하고, 자주 누르는 버튼은 40~44px 정도를 디자인 목표로 권한다. 주사위 회전에도 reduced-motion 대응을 검토한다. [W3C 타깃 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### 도전해 볼 변화

유행하는 장식으로 전면 교체하기보다 **캐릭터별 다음 행동 + 출처가 보이는 데이터**에 집중하는 것을 권한다.

- 배메 마북 체크리스트 → 해당 몬스터 → 출현 맵으로 이어지는 개인 진행 카드.
- `공식 확정 / 커뮤니티 제보 / 원작 참고 / 미확인` 배지를 데이터 필드에도 적용.
- 긴 가이드는 요약·준비물·실측·원문을 단계적으로 펼치는 구성으로 변경.
- 실제 사용자 반응성 측정 후 개선: INP 목표는 모바일/데스크톱별 p75 200ms 이하. 이번 검사에서는 실사용 INP/CrUX를 측정하지 않았으므로 성능 합격 판정은 하지 않는다. [web.dev INP 가이드](https://web.dev/articles/optimize-inp)

### 아직 완성됐다고 볼 수 없는 부분

- **퀘스트**: `/quests` 자체가 임시 ID·참고 데이터임을 경고한다. 에델슈타인 117개는 원작 공지 이름 기반이며, 로컬의 해당 117개 모두 EXP 보상 필드가 0이다. 이는 인게임에서 보상이 없다는 뜻이 아니다. 아모리아 기존 5개도 상세 조건/보상 미확인 상태다. `0`과 `미확인`을 분리하고, 별도 `mapledb_quests` 정규 ID 자료와 이름·선행·NPC를 대조해야 한다.
- **기존 퀘스트 조건**: 운영 `/api/quests/9`의 마야 퀘스트 조건에 `다크스텀프 드롭 아이템 50/20/40개`처럼 아이템명이 소실된 값이 반복된다. 공략에 바로 쓰기 어려우며 원문 재파싱이 필요하다. 일부 1~5메소 보상 값도 감사 스크립트에 잡히지만, 정확한 오입력 여부와 정답은 원문 대조 전 단정하지 않는다.
- **스폰 정보**: 광석 이터의 운영 `spawn_maps=[]`. 패치 스크립트는 공지 맵과 원작 서식지가 일치하지 않아 의도적으로 보류했다. 다른 신규 스폰도 원작 지역 순서 기반 수동 매핑이 있으므로 모두 인게임 실측값은 아니다. 정확한 맵명/ID가 확보될 때까지 참고 표시가 필요하다.
- **출처**: 광석 이터 HP/EXP는 새 실측인데 API `source_url`은 여전히 GMS/95다. 필드별 출처·관측일·본섭/버닝·환산식을 저장해야 한다. 특히 버닝 EXP를 본섭으로 환산한 수치는 직접 측정값과 구별해야 한다.
- **커뮤니티 의견의 과도한 확정 표현**: 배메 가이드의 `오라는 ... 파티사냥 시너지가 없다는 실측`은 연결된 글에서 검증 과정이 제시되지 않은 개인 평가다. `커뮤니티 의견 1건`으로 낮추고 적용 범위/실제 파티 효과는 별도로 검증해야 한다. [연결된 커뮤니티 글](https://gall.dcinside.com/mgallery/board/view/?id=mapleland&no=3943616)

원작 기준도 하나로 묶으면 안 된다. 처음 제공된 넥슨 링크는 **2010-07-22 KMS 1.2.105** 공지다. 현재 배메 가이드는 이를 메랜의 빅뱅 전 수치와 분리해 설명하고 있어 이 부분은 유지해야 한다. 레벨별 수치와 퀘스트 완성도를 해당 공지 하나로 보증할 수는 없다. [넥슨 원문](https://archive.maplestory.nexon.com/News/Update/147?p=12)

1. **머지 후 확인**: 앱 시작 시 seed sync 다음 `repair_skill_classes`/`repair_quest_conditions`를 적용하고 변경이 있으면 통합 검색 색인도 갱신한다. 배포 후 `/api/health`, `/api/skills/91`, `/api/quests/9`, `/api/events`를 확인한다. 원본은 `skill_aliases.original_json`, `quest_audit_backups.original_json`에 보존된다. 사용자 게임/길드 기록은 수정하지 않는다.
2. **크롤러 운영 원인**: 관리자 인증으로 `GET /api/weekly-news/crawl-status` 또는 material의 `crawl_status`를 확인한다. `enabled`, 최근 run의 상태·건수, `last_success_at`, `needs_attention`을 점검한다. 운영에서 0건이었던 원인을 로컬 수집 성공만으로 해결됐다고 단정하지 않는다.
3. **주간 발행 전**: 신규 공식 글 + 수정 공식 글 + 커뮤니티 글 + 수집 경고를 함께 검토한다. `updated_at`은 실제 편집 시각이 아닌 **수정 감지 시각**이다. 이미 발행한 주간호를 이번 PR에서 자동 재발행/수정하지 않는다.
4. **인게임 증거 대기**: 에델 117개 등의 정확한 보상·NPC·선행조건, 광석 이터 정확한 메랜 맵 ID, 미확인 마북 드롭/확률은 여전히 검증 대기다. 미확인/참고 표시는 구현했지만 이 값들을 새 확정 데이터로 채우지는 않았다.
5. **성능**: 선택형 로컬 진단의 표본과 전 사용자 실측은 다르다. 실제 사용자 모바일/데스크톱별 INP p75 200ms 충족은 표본 수집 후 평가해야 하며, 이번 PR에서 합격을 보증하지 않는다.
